Mục Tiêu Học Tập Trọng Tâm

1. 12-Factor App Config
Tách biệt hoàn toàn code và configuration. Sử dụng Pydantic Settings đọc biến môi trường, thiết lập fail-fast khi thiếu secret quan trọng.
2. Multi-stage Container
Xây dựng Dockerfile 2 tầng siêu nhẹ (<500MB), tận dụng layer cache, chạy non-root user và tuân thủ nguyên tắc bảo mật image.
3. API Key & Cost Guard
Bảo vệ API qua xác thực secrets.compare_digest, giới hạn tốc độ (rate limit) sliding-window Redis ZSET và chốt chặn chi phí trước khi gọi LLM.
4. Liveness & Readiness
Phân biệt rạch ròi endpoint /health (tiến trình sống) và /ready (sẵn sàng kết nối phụ thuộc như Redis).
5. Stateless & Scale Ngang
Lưu trữ chat history trong Redis có TTL và Max Turns, xử lý tín hiệu SIGTERM để shutdown êm ái (graceful shutdown).
6. Production Cloud Deploy
Đưa ứng dụng lên hạ tầng Cloud thực tế (Railway / Render) với public HTTPS, đọc biến $PORT dynamic.

  • Docker Desktop & Docker Compose đang chạy nền.

source .venv/bin/activate

⚙️ 2. Biến môi trường & Redis

  • Khởi động Redis: docker compose up -d redis

CP0 — Setup & Kiểm Tra Môi Trường

Làm Gì
  • Tạo hoặc đổi tên repo theo định dạng chuẩn quy định.
  • Tạo Python virtual environment và cài đặt requirements.txt.
  • Sao chép file mẫu: cp .env.example .env và sinh API Key.
  • Bật Redis bằng docker compose up -d redis hoặc cấu hình tạm REDIS_URL=fake://.
Sản Phẩm Đạt Được
  • Repository GitHub có cấu trúc thư mục hoàn chỉnh, đúng tên.
  • Môi trường ảo .venv kích hoạt thành công, không thiếu package.
  • File .env cục bộ có đủ key cần thiết và KHÔNG bị lộ.
  • Redis server đang chạy hoặc backend fake đã sẵn sàng.
Hiểu Bản Chất
  • Bảo mật bí mật: Vì sao .env bắt buộc phải nằm trong file ignore không được đẩy lên remote.
  • Red-Green-Refactor: Chạy test trước khi viết code sẽ gặp lỗi (đỏ) là hoàn toàn bình thường.
  • Hiểu vai trò của file requirements và cách ly dependencies.
Tự Kiểm Tra (Self-Check)
  • Chạy lệnh kiểm thử ban đầu: 
    pytest tests/ -v -m "not docker"
  • Lệnh phải thực thi bình thường (không văng lỗi ModuleNotFoundError hay cú pháp).
🟢 CHECKPOINT 1 · START +20–60 PHÚT · 15 ĐIỂM

CP1 — 12-Factor Config, Health & Logging

Làm Gì
  • Hoàn thiện app/config.py: Sử dụng Pydantic BaseSettings khai báo đủ 6 trường cấu hình.
  • Thiết lập trường agent_api_key bắt buộc (fail-fast nếu thiếu).
  • Cấu hình logging định dạng JSON 1 dòng trong app/logging_utils.py.
  • Tạo endpoint /health trả 200 OK độc lập với các phụ thuộc ngoài.
Sản Phẩm Đạt Được
  • Đối tượng Settings tự động load và validate biến môi trường chính xác.
  • Logs in ra console chuẩn cấu trúc JSON 1 dòng (timestamp, level, event, metadata).
  • Endpoint /health luôn trả {"status": "ok"} ngay cả khi Redis tắt.
Hiểu Bản Chất
  • Nguyên tắc III của 12-Factor: Code không đổi qua các môi trường, chỉ có cấu hình thay đổi theo môi trường.
  • Fail-fast: Ứng dụng phải dừng ngay từ lúc khởi động nếu cấu hình bắt buộc không hợp lệ.
  • Liveness probe: Kiểm tra tiến trình web có sống không; không được gọi DB/Redis tại đây để tránh cascade failure.
Tự Kiểm Tra (Self-Check)
  • Chạy bộ test suite cho CP1: 
    pytest tests/test_cp1.py -v
  • Tất cả các ca kiểm thử về config validation, log JSON format và health check phải PASS xanh hoàn toàn.
🟢 CHECKPOINT 2 · START +60–105 PHÚT · 15 ĐIỂM

CP2 — Multi-stage Docker & Compose

Làm Gì
  • Xây dựng Dockerfile 2 giai đoạn: stage 1 builder (cài wheels), stage 2 runner (chỉ copy wheels, python-slim).
  • Tạo non-root user (appuser) và gán quyền sở hữu mã nguồn.
  • Khai báo chỉ thị HEALTHCHECK và lệnh khởi động đọc biến $PORT.
  • Viết .dockerignore và docker-compose.yml cho 2 service: agent & redis.
Sản Phẩm Đạt Được
  • Docker image gọn nhẹ (kích thước tối ưu < 500MB).
  • Container thực thi dưới user đặc quyền thấp, loại bỏ nguy cơ root breakout.
  • Lệnh docker compose up -d khởi chạy thành công cả ứng dụng và Redis trên mạng nội bộ.
Hiểu Bản Chất
  • Layer Caching: Luôn COPY requirements.txt và cài đặt trước khi COPY . ..
  • Bảo mật: Không chạy process trong container dưới quyền root; không để rò rỉ build cache và file .env vào image context.
  • Cloud readiness: Platform cloud sẽ tự gán ngẫu nhiên $PORT, ứng dụng phải lắng nghe trên cổng này.
Tự Kiểm Tra (Self-Check)
  • Kiểm tra tự động và build thử nghiệm: 
    pytest tests/test_cp2.py -v
docker build -t day12-agent:prod .
docker compose up -d
curl http://localhost:8000/health

🟢 CHECKPOINT 4 · START +160–200 PHÚT · 20 ĐIỂM

CP4 — Scaling, Readiness & Graceful Shutdown

Làm Gì
  • Quản lý session chat trong Redis (app/store.py): Cắt tỉa lịch sử theo MAX_HISTORY_TURNS và gán SESSION_TTL_SECONDS.
  • Viết endpoint /ready: Gửi lệnh ping() đến Redis; trả 200 OK nếu sẵn sàng, trả 503 Service Unavailable nếu mất kết nối.
  • Cài đặt Signal Handler bắt tín hiệu SIGTERM và SIGINT trong app/lifecycle.py, chain tới handler cũ.
Sản Phẩm Đạt Được
  • FastAPI backend hoàn toàn stateless, có thể scale ngang thành nhiều container mà không lệch state.
  • Endpoint /ready báo trạng thái tin cậy cho load balancer điều phối traffic.
  • Khi nhận lệnh stop từ Docker/K8s, ứng dụng dọn dẹp kết nối êm ái trước khi thoát.
Hiểu Bản Chất
  • Liveness vs Readiness: /health (tiến trình có treo không? Nếu treo restart) vs /ready (phụ thuộc có đủ không? Chưa đủ thì ngừng cấp traffic).
  • Stateless: Bất kỳ instance nào cũng có thể xử lý bất kỳ request nào vì state nằm tập trung tại Redis.
Tự Kiểm Tra (Self-Check)
  • Chạy test suite cho CP4: 
    pytest tests/test_cp4.py -v
  • Thử tắt Redis và xác nhận: /health vẫn trả 200, nhưng /ready phải trả về 503!

CP5 — Cloud Deployment & Fallback Policy

☁️ Kịch bản 1: Live Cloud Deploy (15/15 Điểm)
Deploy ứng dụng lên Railway hoặc Render kèm Cloud Redis; cấu hình đầy đủ biến môi trường trên Dashboard platform.
⚠️ Kịch bản 2: LOCAL_FALLBACK=true (Tối đa 9/15 Điểm)
Nếu gặp sự cố thẻ/tài khoản platform: bật cờ export LOCAL_FALLBACK=true để test cục bộ; điểm tối đa 9/15.
Làm Gì
  • Deploy HTTPS URL công khai lên Railway hoặc Render kèm Cloud Redis.
  • Cấu hình Environment Variables trên Platform Dashboard.
  • Soạn thảo DEPLOYMENT.md kèm lệnh curl mẫu và ảnh screenshots.
  • Fallback nếu có sự cố: LOCAL_FALLBACK=true.
Sản Phẩm Đạt Được
  • URL HTTPS công khai + Redis đám mây + biến môi trường trên platform.
  • File DEPLOYMENT.md đầy đủ URL, curl test, và ảnh trong screenshots/.
  • Hoặc cờ fallback: LOCAL_FALLBACK=true ➔ CP5 tối đa 9/15 điểm.
Hiểu Bản Chất
  • Cách platform cấp phát dynamic $PORT và ứng dụng phải bind vào cổng này.
  • Phân biệt Build Logs (đóng gói image) vs Runtime Logs (xử lý request).
  • Nơi lưu trữ an toàn Secrets trên Dashboard, không commit file .env.
  • Chẩn đoán lỗi healthcheck và readiness khi deploy thực tế.
Tự Kiểm Tra
  • Chạy bộ test suite cho CP5: 
    pytest tests/test_cp5.py -v
  • Thực thi trực tiếp các lệnh curl kiểm chứng được nêu trong DEPLOYMENT.md tới HTTPS URL công khai.
